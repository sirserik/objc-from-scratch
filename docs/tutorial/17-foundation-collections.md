# Глава 17. Foundation: коллекции

В главе 4 ты собирал данные в си-массив: `int prices[10];`. Удобно, пока
знаешь размер заранее и хранишь примитивы. Но стоит захотеть «список
имён, который растёт сам», «телефонную книгу имя→номер» или «набор без
повторов» — и голый Си заставляет писать всё это руками.

Foundation даёт три готовых контейнера на все случаи: **NSArray**
(упорядоченный список), **NSDictionary** (пары ключ→значение) и
**NSSet** (набор уникальных элементов). У каждого есть изменяемый
брат — `NSMutable…`. В этой главе разберём их по методам, а в конце
построим маленький учёт товаров: посчитаем продажи, выделим уникальные
категории и составим рейтинг.

## Что мы сделаем

- Создадим неизменяемый массив литералом `@[...]` и переберём его.
- Научимся менять `NSMutableArray`: добавлять, вставлять, удалять.
- Соберём словарь `@{...}` и достанем значения по ключу.
- Сложим уникальные элементы в множество и пересечём два множества.
- Отсортируем массив блоком-компаратором и отфильтруем предикатом.
- Споткнёмся о классический краш «мутация во время перебора» и починим.
- Построим сквозной пример — учёт товаров за день.

## Три контейнера и зачем их три

Представь, что ведёшь маленькую кофейню. Тебе нужно:

- **порядок продаж за день** — что за чем пробили. Список с порядком и
  повторами → массив;
- **остаток на складе** — «кофе: 12, чай: 5». Связь имя→число, ищем по
  имени → словарь;
- **какие категории сегодня продавались** — «горячее», «холодное», без
  повторов и порядка → множество.

Один и тот же товар может лежать во всех трёх — контейнеры дополняют
друг друга.

> **Отличие от Си.** В Си из коробки есть только массив, да и тот
> фиксированной длины и хранит примитивы по значению. «Словаря» и
> «множества» в языке нет вовсе — их пишут руками (хеш-таблицы,
> деревья) или тащат стороннюю библиотеку. В Foundation это готовые,
> вылизанные десятилетиями классы: бери и пользуйся.

Ещё одно общее правило, важное с самого начала: **коллекции Foundation
хранят объекты, а не примитивы.** Положить туда `int` напрямую нельзя —
сначала упакуй его в `NSNumber` (глава 16). И **`nil` класть нельзя** —
для «пустого места» есть особый объект `NSNull` (тоже глава 16). Почему
так — увидим по ходу.

## NSArray: упорядоченный неизменяемый список

Самый частый способ создать массив — **литерал** `@[...]`. Тот же знак
`@`, что превращал текст в `NSString`, а число в `NSNumber`, здесь
строит готовый `NSArray`:

```objc
NSArray *fruits = @[ @"яблоко", @"банан", @"вишня" ];
```

Внутри — три объекта `NSString`. Запятые разделяют элементы, и можно
ставить запятую даже после последнего — компилятор не против.

Разберём основные сообщения массиву.

### count, индексы, края

```objc
NSLog(@"всего: %lu", (unsigned long)[fruits count]);

NSString *first = [fruits objectAtIndex:0];
NSString *second = fruits[1];          /* субскрипт */
```

- `count` — сколько элементов. Возвращает `NSUInteger` (беззнаковое
  целое). Печатаем его как `%lu`, приведя к `(unsigned long)` — это
  снимает предупреждение о размере типа на разных платформах.
- `objectAtIndex:` — взять элемент по номеру. **Нумерация с нуля**, как
  в Си: первый элемент — индекс 0.
- `fruits[1]` — то же самое, но короче. Квадратные скобки с числом
  компилятор разворачивает в вызов `objectAtIndex:`. Это **субскрипт**
  (subscript), привычная по Си запись `arr[i]`.

> **Отличие от Си.** Запись `fruits[1]` выглядит как сишный доступ к
> массиву, но это не разыменование адреса по смещению. Это вызов метода
> `objectAtIndexedSubscript:`, который сам проверит границы. Выйдешь за
> край — получишь аккуратное исключение с понятным текстом, а не молчаливый
> выход за пределы памяти и мусор, как в Си.

Чтобы безопасно взять края, есть два метода, которым не нужен индекс:

```objc
NSLog(@"перв=%@ посл=%@", [fruits firstObject], [fruits lastObject]);
```

`firstObject` и `lastObject` возвращают первый и последний элементы.
Их прелесть в том, что на **пустом** массиве они вернут `nil`, а не
упадут. Сравни: `[empty objectAtIndex:0]` на пустом массиве — это
исключение и краш.

### Поиск: containsObject: и indexOfObject:

```objc
BOOL hasBanana = [fruits containsObject:@"банан"];     /* 1 */
NSUInteger idx = [fruits indexOfObject:@"вишня"];      /* 2 */
NSUInteger miss = [fruits indexOfObject:@"манго"];     /* NSNotFound */
NSLog(@"манго найдено? %d", miss != NSNotFound);        /* 0 */
```

- `containsObject:` — есть ли такой элемент. Возвращает `BOOL`.
- `indexOfObject:` — на каком он месте. Если нет — возвращает особое
  значение `NSNotFound` (это просто очень большое число). Сравнивай
  результат именно с `NSNotFound`, не с `-1`.

Важная деталь: оба метода ищут не «тот же самый объект в памяти», а
**равный по содержанию**. Они зовут у элементов `isEqual:`. Поэтому
строка `@"банан"`, набранная заново, находит свою копию в массиве, хотя
это, возможно, другой объект в памяти. Для строк это `isEqualToString:`
под капотом (см. главу 15 про `==` против `isEqual:`).

### componentsJoinedByString:

```objc
NSLog(@"список: %@", [fruits componentsJoinedByString:@", "]);
// → яблоко, банан, вишня
```

`componentsJoinedByString:` склеивает все элементы в одну строку,
вставляя между ними разделитель. Работает, когда элементы — строки.
Очень удобно для печати: иначе `NSLog(@"%@", fruits)` выведет массив в
служебном формате со скобками и (для кириллицы) с `\U…`-кодами.

## NSMutableArray: тот же массив, но изменяемый

`NSArray` после создания не меняется — ни добавить, ни удалить. Когда
нужно менять, берём `NSMutableArray` (mutable — изменяемый). Его обычно
создают пустым и наполняют:

```objc
NSMutableArray *cart = [[NSMutableArray alloc] init];
[cart addObject:@"хлеб"];               /* в конец */
[cart addObject:@"молоко"];
[cart insertObject:@"соль" atIndex:0];  /* вставить на позицию 0 */
[cart replaceObjectAtIndex:1 withObject:@"батон"];
[cart removeObject:@"молоко"];          /* удалить по значению */
[cart removeObjectAtIndex:0];           /* удалить по индексу */
```

- `addObject:` — добавить в конец. Массив растёт сам, заранее размер
  знать не нужно.
- `insertObject:atIndex:` — вставить на конкретную позицию; всё, что
  правее, сдвигается.
- `replaceObjectAtIndex:withObject:` — заменить элемент на месте.
- `removeObject:` — убрать **все** элементы, равные данному (по
  `isEqual:`).
- `removeObjectAtIndex:` — убрать один элемент по номеру.

Есть ещё конструктор-подсказка:

```objc
NSMutableArray *big = [NSMutableArray arrayWithCapacity:100];
```

`arrayWithCapacity:` намекает, что элементов будет около сотни, чтобы
массив сразу выделил память и реже перевыделял её при росте. Это **не
предел**: добавишь больше — массив спокойно вырастет. Чисто оптимизация;
если не уверен — просто `init`.

> **Отличие от Си.** Си-массив `int a[10]` — это десять ячеек подряд,
> фиксированных навсегда, и хранят они числа **по значению**.
> `NSMutableArray` растёт и сжимается сам, а хранит **ссылки на
> объекты**. Числа в нём лежат упакованными в `NSNumber` (глава 16):
> сам массив про `int` ничего не знает, он знает только объекты.

### nil класть нельзя

Попытка `[cart addObject:nil]` — это краш с исключением. `nil` для
коллекции означает «конец списка аргументов» и вообще «ничего», поэтому
как значение он запрещён. Если по смыслу нужна «дырка» или «значение
отсутствует» — клади объект-заглушку `NSNull`:

```objc
[cart addObject:[NSNull null]];   /* законная «пустышка» */
```

`[NSNull null]` всегда возвращает один и тот же общий объект. Доставая
его, ты сравниваешь: `if (obj == [NSNull null]) { ... }`. Подробно
`NSNull` разбирали в главе 16.

## Перебор массива

### Быстрый перебор for-in

Главный способ пройти по коллекции — **быстрый перебор** (fast
enumeration), цикл `for-in`:

```objc
for (NSString *f in fruits) {
    NSLog(@"for-in: %@", f);
}
```

Читается как «для каждого `f` из `fruits`». На каждом витке `f`
становится очередным элементом. Не нужен ни счётчик, ни `count`, ни
`objectAtIndex:` — компилятор и runtime берут это на себя, и делают это
быстро (отсюда «быстрый»).

> **Отличие от Си.** Сишный `for (int i = 0; i < n; i++)` крутит
> счётчик и сам лезет по индексу. `for-in` — другое: ты получаешь сразу
> **значения**, а не номера, и не управляешь шагом. Платишь за удобство
> одним ограничением: **коллекцию нельзя менять прямо во время такого
> перебора** (об этом — отдельный раздел ниже, там и краш покажем).

### enumerateObjectsUsingBlock: с индексом и stop

Когда нужен не только элемент, но и его номер, помогает перебор блоком
(блоки — глава 12):

```objc
[fruits enumerateObjectsUsingBlock:^(id obj, NSUInteger i, BOOL *stop) {
    NSLog(@"блок [%lu] = %@", (unsigned long)i, obj);
    if (i == 1) {
        *stop = YES;   /* прерываем перебор досрочно */
    }
}];
```

Блок получает три параметра:

- `obj` — текущий элемент;
- `i` — его индекс;
- `stop` — указатель на флаг. Записав `*stop = YES`, ты говоришь
  «дальше не надо», и перебор останавливается. Это замена сишному
  `break`.

В нашем примере перебор оборвётся после индекса 1 — третий элемент
(`вишня`) уже не попадёт в лог.

### Обратный перебор

Чтобы пройти массив с конца, добавим опцию:

```objc
[fruits enumerateObjectsWithOptions:NSEnumerationReverse
                         usingBlock:^(id obj, NSUInteger i, BOOL *stop) {
    NSLog(@"обратно [%lu] = %@", (unsigned long)i, obj);
    (void)stop;
}];
```

`NSEnumerationReverse` — флаг «идти от последнего к первому». Индексы
при этом остаются настоящими (2, 1, 0), просто порядок обхода обратный.
Строка `(void)stop;` нужна, только чтобы компилятор не ругался на
неиспользованный параметр под `-Wextra`; никакого действия она не несёт.

## NSDictionary: пары ключ → значение

Словарь хранит связи «ключ → значение»: по ключу мгновенно достаёшь
значение. Литерал — `@{ ключ : значение, ... }`:

```objc
NSDictionary *colors = @{
    @"яблоко" : @"красный",
    @"банан"  : @"жёлтый",
    @"слива"  : @"синий",
};
```

Слева от двоеточия — ключ, справа — значение. Здесь и ключи, и значения
— строки, но значением может быть любой объект (число, массив, другой
словарь).

### Доступ по ключу

```objc
NSString *a = [colors objectForKey:@"яблоко"];   /* метод */
NSString *b = colors[@"банан"];                  /* субскрипт */
NSString *miss = colors[@"манго"];               /* нет ключа → nil */
```

- `objectForKey:` — взять значение по ключу.
- `colors[@"банан"]` — то же короче (субскрипт по ключу разворачивается
  в `objectForKeyedSubscript:`).
- Нет такого ключа — вернётся `nil`, а **не** падение. В логе `nil`
  печатается как `(null)`.

`count` у словаря — это число пар.

### allKeys, allValues

```objc
NSLog(@"ключи: %@", [[colors allKeys] componentsJoinedByString:@", "]);
```

`allKeys` отдаёт массив всех ключей, `allValues` — массив всех значений.
Порядок в этих массивах **не определён**: словарь хранит пары так, как
ему удобно для быстрого поиска, а не в порядке добавления.

### NSMutableDictionary

Изменяемый словарь наполняют после создания:

```objc
NSMutableDictionary *stock = [[NSMutableDictionary alloc] init];
[stock setObject:@10 forKey:@"яблоко"];   /* метод */
stock[@"банан"] = @5;                       /* субскрипт-присваивание */
stock[@"яблоко"] = @12;                     /* тот же ключ → замена */
[stock removeObjectForKey:@"слива"];        /* убрать пару */
```

- `setObject:forKey:` — положить значение под ключ.
- `stock[@"банан"] = @5;` — то же самое короче.
- Записать по **существующему** ключу — значит **заменить** значение, а
  не добавить вторую пару. Ключи в словаре уникальны.
- `removeObjectForKey:` — удалить пару по ключу.

### Перебор словаря

`for-in` по словарю идёт **по ключам**:

```objc
for (NSString *fruit in colors) {
    NSLog(@"%@ → %@", fruit, colors[fruit]);
}
```

Если нужны сразу ключ и значение — есть блочный вариант:

```objc
[stock enumerateKeysAndObjectsUsingBlock:^(id key, id obj, BOOL *stop) {
    NSLog(@"склад: %@ = %@ шт.", key, obj);
    (void)stop;
}];
```

### Требования к ключам

Ключ словаря — не любой объект. Он должен:

- **поддерживать `isEqual:` и `hash`** — словарь по хешу раскладывает
  пары по «корзинам» и сравнивает ключи на равенство. У `NSString` и
  `NSNumber` это уже сделано правильно, поэтому они — идеальные ключи;
- **копироваться** — при добавлении словарь делает `copy` ключа и
  хранит копию. Это защита: если ты потом изменишь свой объект-ключ,
  словарь не «потеряет» пару. Поэтому ключом обычно берут неизменяемые
  объекты — те же строки.

Значение копироваться не обязано — оно хранится по ссылке, как в
массиве.

> **Отличие от Си.** Чтобы получить такое в Си, ты бы писал хеш-таблицу
> сам: функцию хеширования, разрешение коллизий, рост таблицы.
> `NSDictionary` всё это уже умеет, а от твоих ключей просит лишь
> корректные `hash`/`isEqual:` — у стандартных классов они уже есть.

## NSSet: уникальные элементы без порядка

Множество хранит **уникальные** объекты и не помнит порядок. Его сила —
в одном: мгновенная проверка «есть ли такой элемент». Часто множество
делают из массива, и дубликаты сами схлопываются:

```objc
NSArray *raw = @[ @"кофе", @"чай", @"кофе", @"сок", @"чай" ];
NSSet *drinks = [NSSet setWithArray:raw];
// в raw 5 элементов, в drinks — 3
```

```objc
NSLog(@"есть чай? %d", [drinks containsObject:@"чай"]);   /* 1 */
NSLog(@"есть морс? %d", [drinks containsObject:@"морс"]); /* 0 */
```

`containsObject:` у множества работает по тому же `isEqual:`/`hash`, но
по скорости это совсем другое дело, чем у массива.

### Когда множество лучше массива

`containsObject:` у массива в худшем случае перебирает все элементы по
очереди — чем длиннее массив, тем дольше. У множества проверка идёт по
хешу и почти не зависит от размера. Правило простое: **если главная
операция — «а есть ли тут такой?», и порядок не важен, бери множество.**
Список «кого уже обработали», «какие id видели», «множество тегов» —
классические задачи для `NSSet`.

### Операции над множествами

`NSMutableSet` умеет складывать множества как в школьной теории:

```objc
NSMutableSet *cafeA = [NSMutableSet setWithArray:@[ @"кофе", @"чай",
                                                    @"какао" ]];
NSSet *cafeB = [NSSet setWithArray:@[ @"чай", @"сок", @"какао" ]];

NSMutableSet *common = [cafeA mutableCopy];
[common intersectSet:cafeB];   /* пересечение: только общие */

NSMutableSet *all = [cafeA mutableCopy];
[all unionSet:cafeB];          /* объединение: всё вместе */

NSMutableSet *only = [cafeA mutableCopy];
[only minusSet:cafeB];         /* разность: A без того, что есть в B */
```

- `intersectSet:` — оставить только элементы, которые есть **и там, и
  там**.
- `unionSet:` — добавить всё из второго множества.
- `minusSet:` — выкинуть из первого всё, что встречается во втором.

Эти методы меняют сам объект, поэтому мы каждый раз работаем с
`mutableCopy`, чтобы не испортить исходный `cafeA`. И `addObject:` у
множества молча игнорирует дубликат — добавить «чай» второй раз ничего
не изменит.

### NSOrderedSet — уникальность плюс порядок

Иногда нужны обе вещи разом: и без повторов, и с сохранением порядка.
Это `NSOrderedSet`:

```objc
NSOrderedSet *menu = [NSOrderedSet orderedSetWithArray:
                      @[ @"суп", @"салат", @"суп", @"чай" ]];
// → суп, салат, чай  (второй «суп» отброшен, порядок сохранён)
NSLog(@"первый в меню: %@", [menu firstObject]);
```

Он как массив (есть `firstObject`, индексы, `array`), но с гарантией
уникальности. Платишь за это памятью и чуть большей сложностью —
поэтому берут его реже, по реальной нужде.

## Сортировка и фильтрация

### sortedArrayUsingComparator:

Отсортировать массив можно блоком-**компаратором** — он сравнивает два
элемента и говорит, кто раньше:

```objc
NSArray *byLength = [words sortedArrayUsingComparator:
    ^NSComparisonResult(id a, id b) {
        NSUInteger la = [(NSString *)a length];
        NSUInteger lb = [(NSString *)b length];
        if (la < lb) return NSOrderedAscending;
        if (la > lb) return NSOrderedDescending;
        return NSOrderedSame;
    }];
```

Блок получает два элемента `a` и `b` и обязан вернуть `NSComparisonResult`
— одно из трёх значений:

- `NSOrderedAscending` — `a` должен идти **раньше** `b`;
- `NSOrderedDescending` — `a` должен идти **позже** `b`;
- `NSOrderedSame` — порядок между ними не важен.

`sortedArrayUsingComparator:` возвращает **новый** отсортированный массив,
исходный не трогает. Здесь мы сортируем по длине строки.

Для частых случаев ничего изобретать не надо: у строк уже есть готовый
компаратор `compare:`, который сравнивает по алфавиту. Тогда блок
сводится к одной строке:

```objc
NSArray *byAbc = [words sortedArrayUsingComparator:
    ^NSComparisonResult(id a, id b) {
        return [(NSString *)a compare:b];
    }];
```

### sortUsingDescriptors: кратко

Когда сортируешь массив объектов (или словарей) по какому-то их полю,
удобнее **дескриптор сортировки** `NSSortDescriptor` — ты просто
называешь ключ и направление:

```objc
NSMutableArray *people = [@[
    @{ @"name" : @"Аня",  @"age" : @30 },
    @{ @"name" : @"Боря", @"age" : @22 },
    @{ @"name" : @"Вера", @"age" : @27 },
] mutableCopy];

NSSortDescriptor *byAge =
    [NSSortDescriptor sortDescriptorWithKey:@"age" ascending:YES];
[people sortUsingDescriptors:@[ byAge ]];
```

`sortDescriptorWithKey:ascending:` — «сортируй по полю `age`, по
возрастанию». `sortUsingDescriptors:` принимает **массив** дескрипторов:
первый задаёт основной порядок, второй разруливает совпадения, и так
далее. В отличие от `sortedArray…`, метод `sortUsingDescriptors:`
меняет сам мутабельный массив на месте.

### filteredArrayUsingPredicate: и NSPredicate

Отобрать из массива подходящие элементы помогает **предикат**
`NSPredicate` — условие, записанное строкой:

```objc
NSPredicate *longOnes =
    [NSPredicate predicateWithFormat:@"length > 3"];
NSArray *filtered = [words filteredArrayUsingPredicate:longOnes];
// останутся только слова длиннее трёх букв
```

`predicateWithFormat:` строит условие из текста. `filteredArrayUsingPredicate:`
прогоняет каждый элемент через это условие и возвращает новый массив из
тех, для кого оно истинно. Здесь `length` — свойство строки; предикат
сам спрашивает его у каждого элемента. Язык предикатов богат
(`>`, `<`, `==`, `BEGINSWITH`, `CONTAINS`, `AND`, `OR`) — это отдельная
большая тема, пока достаточно почувствовать идею.

### valueForKey: на массиве — тизер KVC

И последний приём, который выглядит как магия:

```objc
NSArray *names = [people valueForKey:@"name"];
// → массив из имён: Аня, Боря, Вера (в текущем порядке people)
```

`valueForKey:`, посланный **массиву**, идёт по всем его элементам,
спрашивает у каждого значение под ключом `name` и собирает результаты в
новый массив. Это первое прикосновение к **KVC** (Key-Value Coding,
кодирование «ключ-значение») — целому механизму доступа к данным по
строковому имени. Полноценно разберём его в главе 20; пока запомни, что
из массива объектов одной строкой достаётся «колонка» их значений.

## Ловушка: мутация во время перебора

Самый частый краш новичка с коллекциями — изменить её прямо посреди
`for-in`. Выглядит невинно: «иду по списку и удаляю ненужное».

```objc
NSMutableArray *a = [@[ @"a", @"b", @"c" ] mutableCopy];
for (NSString *s in a) {
    if ([s isEqualToString:@"b"]) {
        [a removeObject:s];   /* МЕНЯЕМ во время перебора! */
    }
}
```

Запусти — и программа упадёт с исключением:

```text
*** Terminating app due to uncaught exception 'NSGenericException',
reason: '*** Collection <__NSArrayM: 0x…> was mutated while being
enumerated.'
```

Текст прямой: «коллекция была изменена во время перебора». Быстрый
перебор работает по внутреннему состоянию коллекции, и если из-под него
выдернуть элемент, состояние ломается — runtime честно это ловит и
останавливает программу, чтобы ты не получил тихо испорченные данные.

> **Отличие от Си.** В Си цикл по массиву ничего о «целостности
> коллекции» не знает — удалишь элемент на ходу, и в лучшем случае
> пропустишь сосед­ний, в худшем залезешь в чужую память без всякого
> предупреждения. `for-in` в Objective-C, наоборот, специально следит и
> падает громко и сразу. Громкий краш лучше тихого повреждения.

**Правильных способов два.**

Первый — собрать «кандидатов на удаление» в отдельный список, а удалять
уже потом, отдельным проходом:

```objc
NSMutableArray *toRemove = [NSMutableArray array];
for (NSString *s in a) {
    if ([s isEqualToString:@"b"]) {
        [toRemove addObject:s];
    }
}
for (NSString *s in toRemove) {
    [a removeObject:s];        /* a во время этого цикла не перебирается */
}
```

Второй — идти по индексам **с конца**. При проходе от последнего к
первому удаление элемента не сдвигает те, до которых ты ещё не дошёл:

```objc
for (NSInteger i = (NSInteger)[a count] - 1; i >= 0; i--) {
    if ([a[i] isEqualToString:@"b"]) {
        [a removeObjectAtIndex:i];
    }
}
```

То же правило действует и для словаря с множеством: не удаляй из них
ключи/элементы, пока перебираешь их в `for-in`. Собирай ключи на
удаление в массив, потом удаляй.

## Строим с нуля: учёт товаров за день

Соберём всё в одну маленькую программу. Дано — журнал продаж кофейни за
день: просто список проданных товаров, с повторами. Нужно:

1. посчитать, сколько раз продан каждый товар;
2. узнать, сколько **разных** товаров продано;
3. собрать **категории** проданного без повторов;
4. составить рейтинг — от самого ходового к редкому;
5. вычистить «однодневок» (товары, проданных меньше двух раз).

Здесь пригодятся все три контейнера: массив для журнала, словарь для
подсчёта, множество для уникальных категорий.

### Шаг 1. Журнал и подсчёт

```objc
NSArray *sales = @[ @"кофе", @"чай", @"кофе", @"кофе",
                    @"сок", @"чай", @"кофе" ];

NSMutableDictionary *counts = [NSMutableDictionary dictionary];
for (NSString *item in sales) {
    NSNumber *prev = counts[item];          /* nil, если впервые */
    NSInteger n = prev ? [prev integerValue] : 0;
    counts[item] = @(n + 1);
}
```

Идём по журналу. Для каждого товара достаём текущий счётчик. Если товара
ещё не было, `counts[item]` вернёт `nil` — тогда считаем, что было 0.
Прибавляем единицу, упаковываем обратно в `NSNumber` через `@(n + 1)` и
кладём в словарь. Тернарный оператор `prev ? … : 0` аккуратно
обрабатывает «первую встречу».

### Шаг 2. Сколько разных товаров

```objc
NSSet *unique = [NSSet setWithArray:[counts allKeys]];
NSLog(@"разных товаров: %lu", (unsigned long)[unique count]);
```

Ключи словаря — это и есть все различные товары. Завернём их в множество
(хотя ключи и так уникальны, это явно подчёркивает смысл «набор разных»)
и спросим `count`.

### Шаг 3. Категории через множество

```objc
NSDictionary *category = @{
    @"кофе" : @"горячее",
    @"чай"  : @"горячее",
    @"сок"  : @"холодное",
};
NSMutableSet *soldCats = [NSMutableSet set];
for (NSString *item in unique) {
    [soldCats addObject:category[item]];
}
```

У нас есть справочник «товар → категория». Идём по уникальным товарам и
складываем их категории в множество. «Кофе» и «чай» оба «горячее», но в
множестве «горячее» окажется один раз — ровно то, что нужно.

### Шаг 4. Рейтинг

```objc
NSArray *top = [[counts allKeys] sortedArrayUsingComparator:
    ^NSComparisonResult(id a, id b) {
        return [counts[b] compare:counts[a]];   /* по убыванию */
    }];
```

Сортируем ключи по их значениям в `counts`. Хитрость в порядке
сравнения: мы сравниваем `counts[b]` с `counts[a]` (а не наоборот) —
этим переворачиваем сортировку, и более продаваемые встают вперёд. У
`NSNumber` есть готовый `compare:`, который вернёт нужный
`NSComparisonResult`.

### Шаг 5. Чистка однодневок — аккуратно

```objc
NSMutableArray *toRemove = [NSMutableArray array];
for (NSString *item in counts) {
    if ([counts[item] integerValue] < 2) {
        [toRemove addObject:item];
    }
}
for (NSString *item in toRemove) {
    [counts removeObjectForKey:item];
}
```

Помним ловушку: удалять из `counts` прямо в `for-in` нельзя — упадёт.
Поэтому сначала собираем ключи-кандидаты в `toRemove`, и только вторым
проходом удаляем их из словаря.

## Как это работает

Чем три контейнера отличаются внутри:

```text
NSArray       [0]→объект [1]→объект [2]→объект   порядок важен, повторы можно
NSDictionary  hash(ключ) → корзина → значение    поиск по ключу, ключи уникальны
NSSet         hash(объект) → «есть/нет»           только наличие, без порядка
```

Массив — пронумерованные ячейки со ссылками на объекты. Словарь и
множество построены на **хешировании**: спрашивают у ключа/элемента число
`hash`, по нему находят нужную «корзину» и там сравнивают через `isEqual:`.
Поэтому проверка членства у них почти мгновенна и не зависит от размера, а
взамен они не хранят порядок — оттого `allKeys` и перебор множества выдают
элементы «как попало».

## copy vs mutableCopy у коллекций

Коллекции, как и строки (глава 8), отвечают на `copy` и `mutableCopy`:

- `copy` у коллекции возвращает **неизменяемую** версию (`NSArray`,
  `NSDictionary`, `NSSet`);
- `mutableCopy` — **изменяемую** (`NSMutableArray` и т.д.), даже если
  оригинал был неизменяемым. Именно так мы выше делали `[cafeA
  mutableCopy]`, чтобы получить множество, которое не жалко портить.

Важнейшая оговорка: копия **поверхностная** (shallow). Копируется сам
контейнер и его ссылки на элементы — но **не сами элементы**. После
`mutableCopy` у тебя два массива, но объекты внутри — одни и те же:

```objc
NSArray *orig = @[ person1, person2 ];
NSMutableArray *dup = [orig mutableCopy];
// dup — другой массив, но dup[0] и orig[0] — ОДИН и тот же person1
```

Изменишь сам `person1` — изменение «видно» через оба массива, ведь это
один объект. Добавишь объект в `dup` — `orig` не дрогнет, это разные
контейнеры. Для словаря-ключей это безопасно (ключи и так копируются),
а вот за значениями и элементами помни: их разделяют, не дублируют.
Если нужна **глубокая** копия (с дублированием элементов) — её делают
отдельно, это тема для KVC/архивации (глава 19).

## Частые ошибки

- **Положили `nil` в коллекцию.** `addObject:nil`, `setObject:nil
  forKey:…` — мгновенный краш. Для «пусто» используй `[NSNull null]`.
- **Меняете коллекцию в `for-in`.** `NSGenericException … was mutated
  while being enumerated`. Собирай изменения в отдельный список или иди
  по индексам с конца.
- **Пробуете изменить immutable.** `[someNSArray addObject:…]` не
  скомпилируется или упадёт — `NSArray` неизменяем. Нужен
  `NSMutableArray`.
- **Сравниваете элементы через `==`.** Поиск и членство в коллекциях
  идут по `isEqual:`. Свой класс-элемент без правильного `isEqual:`/`hash`
  будет «не находиться» в множестве и словаре. Для строк/чисел всё уже
  сделано.
- **Ждёте порядок от словаря или множества.** Они неупорядочены. Нужен
  порядок — сортируй `allKeys`/`allObjects` или бери массив /
  `NSOrderedSet`.
- **Печатаете кириллицу через `NSLog(@"%@", array)`.** Получишь
  `\U…`-коды. Для людей склеивай `componentsJoinedByString:`.

## Упражнения

1. Заведи `NSMutableArray` из пяти чисел (`NSNumber`). Удали все
   нечётные — сначала наивно, прямо в `for-in` (увидь краш), потом
   правильно, через сбор кандидатов.
2. Построй словарь «город → население» из пяти пар. Выведи только
   города с населением больше миллиона (перебери и сравни `integerValue`).
3. Даны два массива тегов статьи. Через `NSSet` найди общие теги, теги
   только первой статьи и все теги вместе.
4. Отсортируй массив строк по **убыванию** длины через
   `sortedArrayUsingComparator:`. Подсказка: переверни сравнение.
5. Возьми массив словарей `@{ @"name":…, @"price":… }`. Отфильтруй
   предикатом `@"price < 100"`, затем отсортируй по `price` через
   `NSSortDescriptor`.
6. Через `valueForKey:` достань из массива словарей задачи 5 массив всех
   имён одной строкой кода.
