# Глава 15. Foundation: строки

Мы дошли до Foundation — библиотеки, ради которой во многом и существует
вся объектная машинерия из прошлых глав. И первое, с чего начинают почти
любую программу, — это текст. Имя пользователя, путь к файлу, ответ
сервера, цена в чеке: всё это строки.

В главе 4 ты намучился с си-строками: `char *`, ручной поиск `'\0'`,
`strlen`, `strcmp`, и финальный позор — кириллица, где `strlen("Привет")`
выдала `12` вместо `6`. Тогда я обещал: придёт `NSString` и всё станет
по-человечески. Глава пришла.

## Что мы сделаем

- Разберём `NSString` — строку-объект: чем он богаче голого `char *`.
- Научимся создавать строки пятью способами и переводить их в си-строку
  и обратно.
- Поймём `length` — и почему он считает не байты и не «человеческие»
  буквы, а UTF-16 code units (и где это больно бьёт по эмодзи).
- Сравним строки правильно: `isEqualToString:`, а не `==`.
- Пройдёмся по поиску, подстрокам, регистру, обрезке, разбиению и склейке.
- Возьмём `NSMutableString` — строку, которую можно менять на месте.
- Построим с нуля нормализатор логина и прогоним его на живых данных.

## NSString: строка как объект

В Си строка — это кусок памяти с байтами и нулём в конце. Она ничего не
знает о себе: ни длины, ни умения сравниться с соседкой. Всё это ты писал
руками.

`NSString` — наоборот, полноценный **объект**. Он хранит текст внутри
себя и несёт с собой десятки методов: посчитать длину, сравнить, найти
подстроку, перевести регистр, разбить по разделителю. Ты не лазаешь по
байтам — ты посылаешь строке сообщения, как любому другому объекту из
прошлых глав.

> **Отличие от Си.** `char *s = "hi"` — это адрес первого байта и больше
> ничего: ни длины за O(1), ни единого метода. `NSString *s = @"hi"` —
> это объект, который знает свою длину и умеет десятки операций. Маленький
> знак `@` (см. главу 1) превращает мёртвый массив байтов в живую строку.

### Почему NSString неизменяемый

`NSString` **неизменяемый** (immutable): раз создан — его текст менять
нельзя. Нет метода «допиши сюда букву» или «замени третий символ». Любая
операция, которая на вид «меняет» строку, в действительности возвращает
**новую** строку, а исходная остаётся как была.

Звучит как ограничение, но это подарок. Раз строку нельзя испортить, её
можно безбоязненно раздавать: передал `NSString` в три разных места — и
уверен, что никто тайком не перепишет твой текст под ногами. Поэтому в
главе 8 свойства-строки мы помечали `copy` — чтобы зафиксировать
неизменяемый снимок. А когда менять текст всё-таки нужно, для этого есть
отдельный класс `NSMutableString`, наследник `NSString`; к нему дойдём в
конце главы.

## Создаём строки

Откроем `15-create.m` и пройдём по способам создания.

```objc
#import <Foundation/Foundation.h>

int main(void) {
    @autoreleasepool {
        NSString *hello = @"Привет";
        NSLog(@"литерал:        %@", hello);

        NSString *name = @"Серик";
        int age = 40;
        NSString *line = [NSString stringWithFormat:@"%@, тебе %d",
                                                    name, age];
        NSLog(@"формат:         %@", line);

        NSString *line2 = [[NSString alloc] initWithFormat:@"%@!", name];
        NSLog(@"alloc/init:     %@", line2);

        const char *c = "raw C string";
        NSString *fromC = [NSString stringWithUTF8String:c];
        NSLog(@"из C-строки:    %@", fromC);

        const char *back = [fromC UTF8String];
        NSLog(@"в C-строку:     %s (это уже char*)", back);

        NSLog(@"length 'Привет': %lu", (unsigned long)[hello length]);
    }
    return 0;
}
```

Разберём по способам.

**Литерал `@"Привет"`.** Самый частый. Знак `@` перед кавычками говорит
компилятору: «собери из этого готовый объект `NSString`». Такая строка
живёт всё время работы программы, освобождать её не нужно.

**`stringWithFormat:`** — собрать строку из кусков по образцу, ровно как
`printf`, только результат не печатается, а возвращается новой строкой.
Принимает строку формата и значения для подстановки. Спецификаторы те же,
что у `printf`: `%d` для `int`, `%.2f` для `double`, плюс особый `%@` —
«подставь сюда объект» (см. главу 1). Это **фабричный метод класса**
(`+`), поэтому зовём его у самого `NSString`, а не у экземпляра.

**`initWithFormat:`** — то же самое, но в два шага: `alloc` создаёт пустой
объект, `initWithFormat:` его наполняет. Результат идентичен
`stringWithFormat:`; под ARC разницы в памяти ты не почувствуешь. Знать
обе формы полезно: фабрики `stringWith...` и пары `alloc/initWith...`
идут парой почти у каждого класса Foundation.

**`stringWithUTF8String:`** — мост из мира Си. Принимает `const char *`
(си-строку в кодировке UTF-8) и строит из неё `NSString`. Вот зачем тебе
эти страдания с `char *` из главы 4: иногда строки приходят из
си-функций, и их надо втянуть в объектный мир.

**`UTF8String`** — мост в обратную сторону. Возвращает `const char *`:
си-строку в UTF-8. Нужна, когда objc-строку надо отдать в функцию,
которая понимает только `char *` (многие системные вызовы такие).

> **Подводный камень `UTF8String`.** Возвращённый указатель **временный**:
> он живёт не дольше самой строки, а может и меньше — до конца текущего
> пула автоосвобождения. Не сохраняй его «на потом» в долгую переменную —
> используй тут же. Нужна долгоживущая копия — скопируй байты в свой
> буфер (`strdup` или `malloc` + `strcpy` из главы 4) и потом освободи
> его через `free`.

Запускаем:

```text
clang -fobjc-arc -framework Foundation -Wall -Wextra -O2 \
      code/15-create.m -o /tmp/t && /tmp/t
```

```text
литерал:        Привет
формат:         Серик, тебе 40
alloc/init:     Серик!
из C-строки:    raw C string
в C-строку:     raw C string (это уже char*)
length 'Привет': 6
```

Обрати внимание на последнюю строку: `length` для «Привет» дал `6` —
ровно столько букв. В главе 4 `strlen` той же «Привет» выдавала `12`.
Объект считает иначе, чем си-строка. Что именно он считает — следующий
разговор.

## length: длина в UTF-16 code units

`length` возвращает количество символов в строке. Тип результата —
`NSUInteger` (беззнаковое целое). На 64-битном Mac это `unsigned long`,
а на старых 32-битных платформах было `unsigned int`. Поэтому в `NSLog`
его печатают как `%lu` с явным приведением `(unsigned long)` — такая
запись верна на любой платформе, и так советует Apple. Возьмёшь не тот
спецификатор, например `%d`, — компилятор предупредит и сам подскажет
приведение.

Но «количество символов» здесь означает не то, что подсказывает интуиция.
`NSString` показывает текст наружу как последовательность **UTF-16**
(внутри он вправе хранить его компактнее, но это его личное дело), и
`length` считает **code units UTF-16** — 16-битные кусочки, из которых
текст собран. Для
латиницы и кириллицы один code unit = одна буква, поэтому «Привет» дал
честные `6`. Но так везёт не всегда.

> **Отличие от Си.** `strlen` считает **байты** до `'\0'`: «Привет» = 12.
> `length` считает **code units UTF-16**: «Привет» = 6. Ни то, ни другое
> не равно числу «человеческих» символов, как только в тексте появляется
> эмодзи. Запомни три разные величины — байты, code units, символы — это
> не одно и то же.

Разберём ловушку на `15-unicode.m`.

```objc
#import <Foundation/Foundation.h>

int main(void) {
    @autoreleasepool {
        NSString *en = @"cafe";
        NSLog(@"'cafe'  length = %lu", (unsigned long)[en length]);

        NSString *ru = @"Привет";
        NSLog(@"'Привет' length = %lu, UTF-8 байт = %lu",
              (unsigned long)[ru length],
              (unsigned long)strlen([ru UTF8String]));

        NSString *emoji = @"🍎";
        NSLog(@"'🍎'    length = %lu (а человек видит 1 символ)",
              (unsigned long)[emoji length]);

        NSString *flag = @"🇰🇿";
        NSLog(@"'🇰🇿'    length = %lu (а человек видит 1 флаг)",
              (unsigned long)[flag length]);
    }
    return 0;
}
```

Вывод:

```text
'cafe'  length = 4
'Привет' length = 6, UTF-8 байт = 12
'🍎'    length = 2 (а человек видит 1 символ)
'🇰🇿'    length = 4 (а человек видит 1 флаг)
```

Смотри внимательно. `🍎` — один значок для человека, а `length` говорит
`2`. Так вышло потому, что это символ за пределами базового набора, и
UTF-16 кодирует его двумя code units (так называемой суррогатной парой).
Флаг `🇰🇿` ещё хуже: он составлен из двух региональных символов, каждый по
два code unit, итого `length` = `4` при одном видимом флаге.

Мораль: **`length` нельзя путать с «числом символов, которые видит
человек»**. Для латиницы и кириллицы они совпадают, и можно расслабиться.
Но стоит появиться эмодзи или экзотике — и наивный обход «по индексам от
0 до length» разрежет эмодзи пополам и испортит текст.

### Правильный обход по «человеческим» символам

Когда нужно пройтись именно по тому, что человек считает символами,
существует `enumerateSubstringsInRange:options:usingBlock:` с опцией
`NSStringEnumerationByComposedCharacterSequences`. Длинное имя, но смысл
простой: «разбей строку на составные последовательности символов и дай
мне каждую по очереди». Допишем в `15-unicode.m`:

```objc
NSString *mix = @"a🍎🇰🇿b";
NSLog(@"'a🍎🇰🇿b' length = %lu", (unsigned long)[mix length]);

__block NSUInteger humanCount = 0;
NSStringEnumerationOptions opts =
    NSStringEnumerationByComposedCharacterSequences;
[mix enumerateSubstringsInRange:NSMakeRange(0, [mix length])
                        options:opts
                     usingBlock:^(NSString *sub, NSRange subRange,
                                  NSRange enclosing, BOOL *stop) {
    (void)subRange; (void)enclosing; (void)stop;
    humanCount++;
    NSLog(@"  символ #%lu = %@", (unsigned long)humanCount, sub);
}];
NSLog(@"человеческих символов: %lu", (unsigned long)humanCount);
```

Здесь работает **блок** `^{ ... }` из главы 12: метод зовёт его для каждой
найденной последовательности и передаёт саму подстроку `sub` и её диапазон
`subRange`. Переменную `humanCount` мы пометили `__block`, чтобы блок мог
её менять (см. главу 12). Параметры `subRange`, `enclosing`, `stop` нам не
нужны — глушим предупреждение `-Wextra` об их неиспользовании строкой
`(void)subRange;`. Опцию мы вынесли в переменную `opts` только ради
того, чтобы длинное имя не растягивало строку. Вывод:

```text
'a🍎🇰🇿b' length = 8
  символ #1 = a
  символ #2 = 🍎
  символ #3 = 🇰🇿
  символ #4 = b
человеческих символов: 4
```

`length` сказал `8`, а человеческих символов оказалось `4` — и эмодзи с
флагом не порезаны. Запомни этот метод как надёжный способ ходить по
тексту посимвольно, когда туда может попасть юникод.

## Сравнение строк

Самая частая и самая болезненная ошибка новичка. В главе 4 мы пробовали
сравнить си-строки через `==` и получили чушь, потому что `==` сравнивал
адреса, а не буквы. С `NSString` — ровно та же ловушка, и по той же
причине.

Откроем `15-compare.m`:

```objc
NSString *a = @"яблоко";
NSString *b = [NSString stringWithFormat:@"%@", @"яблоко"];

NSLog(@"a == b:                %@", (a == b) ? @"YES" : @"NO");
NSLog(@"isEqualToString:       %@",
      [a isEqualToString:b] ? @"YES" : @"NO");
```

`a` и `b` несут один и тот же текст «яблоко», но это **два разных
объекта**: `b` мы собрали через `stringWithFormat:`, и он лежит в памяти
по другому адресу. Вывод:

```text
a == b:                NO
isEqualToString:       YES
```

`==` дал `NO`, потому что сравнил **адреса** двух объектов, а они разные.
`isEqualToString:` дал `YES`, потому что сравнил **содержимое** — букву к
букве.

> **Отличие от Си.** Это та же история, что с `char *` в главе 4: `==`
> сравнивает указатели (адреса), а не текст. В Си спасал `strcmp`. В
> Objective-C для текста **всегда** `isEqualToString:`. Писать `==` для
> строк — значит спрашивать «это буквально один и тот же объект в памяти?»,
> а почти всегда тебе нужно «одинаковый ли текст?».

`isEqualToString:` принимает другую строку и возвращает `BOOL`: `YES`,
если тексты совпадают посимвольно. Это самый быстрый и точный способ
проверить равенство. (Есть ещё общий `isEqual:` от `NSObject`, но для
строк бери специальный `isEqualToString:` — он быстрее, ведь не тратит
время на проверку типов.)

### Порядок, регистр, префиксы

```objc
NSComparisonResult r = [@"apple" compare:@"banana"];
NSLog(@"compare apple/banana:  %ld (-1 = первый раньше)", (long)r);

NSComparisonResult ci = [@"Apple" caseInsensitiveCompare:@"apple"];
NSLog(@"caseInsensitive:       %ld (0 = равны)", (long)ci);
```

`compare:` отвечает не «равны/нет», а **как они соотносятся по порядку**.
Возвращает `NSComparisonResult` — одно из трёх значений:
`NSOrderedAscending` (−1, получатель идёт раньше), `NSOrderedSame` (0,
равны), `NSOrderedDescending` (1, получатель идёт позже). Это то, что
нужно для сортировки списка строк по алфавиту.

`caseInsensitiveCompare:` — то же сравнение, но без учёта регистра:
«Apple» и «apple» для него равны, результат `0`.

```objc
NSString *file = @"report-2026.pdf";
NSLog(@"hasPrefix report-:     %@",
      [file hasPrefix:@"report-"] ? @"YES" : @"NO");
NSLog(@"hasSuffix .pdf:        %@",
      [file hasSuffix:@".pdf"] ? @"YES" : @"NO");
NSLog(@"containsString 2026:   %@",
      [file containsString:@"2026"] ? @"YES" : @"NO");
```

`hasPrefix:` — начинается ли строка с заданной (удобно проверять схему
`https://` или префикс имени файла). `hasSuffix:` — заканчивается ли
(проверка расширения `.pdf`). `containsString:` — есть ли подстрока
где-то внутри. Все три возвращают `BOOL`. Вывод:

```text
compare apple/banana:  -1 (-1 = первый раньше)
caseInsensitive:       0 (0 = равны)
hasPrefix report-:     YES
hasSuffix .pdf:        YES
containsString 2026:   YES
```

## Поиск и подстроки

`hasPrefix:`/`containsString:` отвечают «да/нет». А когда нужно знать
*где* именно нашлась подстрока, берут `rangeOfString:`. Он возвращает
`NSRange` — простую структуру из двух полей: `location` (с какого индекса)
и `length` (сколько символов). Это чистый Си-`struct`, не объект.

```objc
NSRange range = [file rangeOfString:@"-"];
if (range.location == NSNotFound) {
    NSLog(@"дефис не найден");
} else {
    NSLog(@"дефис на позиции:      %lu", (unsigned long)range.location);
}
```

> **Подводный камень.** Если подстрока не найдена, `rangeOfString:`
> возвращает `{NSNotFound, 0}`: в `location` кладёт особое значение
> `NSNotFound` (это огромное число, `NSIntegerMax`, а не ноль!). Проверять
> надо именно `range.location == NSNotFound`. Забудешь проверку — отдашь
> этот «индекс» в `substringToIndex:` и уронишь программу исключением.

Зная индекс, режем строку на части:

```objc
NSString *namePart = [file substringToIndex:range.location];
NSString *tailPart = [file substringFromIndex:range.location + 1];
```

`substringToIndex:` берёт кусок **от начала до** указанного индекса (сам
индекс не включается). `substringFromIndex:` — **от индекса и до конца**.
Есть и `substringWithRange:`, берущий произвольный диапазон `NSRange`.
Каждый из них, по правилу неизменяемости, возвращает **новую** строку.
Вывод:

```text
дефис на позиции:      6
substringToIndex:      report
substringFromIndex:    2026.pdf
```

> **Подводный камень индексов.** Индексы здесь — это позиции в UTF-16 code
> units, те самые, что считает `length`. Режь так строку, где есть эмодзи,
> по «человеческим» позициям — и можешь рассечь суррогатную пару. Для
> текста с юникодом ищи границы через
> `rangeOfComposedCharacterSequenceAtIndex:` или обход из раздела про
> `length`.

## Регистр и обрезка

```objc
NSLog(@"uppercaseString:       %@", [@"привет" uppercaseString]);
NSLog(@"lowercaseString:       %@", [@"ПРИВЕТ" lowercaseString]);
NSLog(@"capitalizedString:     %@", [@"мир добра" capitalizedString]);

NSString *messy = @"   hello world   ";
NSCharacterSet *ws = [NSCharacterSet whitespaceAndNewlineCharacterSet];
NSString *clean = [messy stringByTrimmingCharactersInSet:ws];
NSLog(@"trim:                  '%@'", clean);
```

`uppercaseString` и `lowercaseString` возвращают новую строку целиком в
верхнем или нижнем регистре. `capitalizedString` делает заглавной первую
букву **каждого слова**.

`stringByTrimmingCharactersInSet:` срезает с **обоих краёв** строки все
символы из переданного набора `NSCharacterSet` — и останавливается, как
только встретит символ не из набора. Внутренние символы не трогает.
`whitespaceAndNewlineCharacterSet` — готовый набор «пробелы, табы и
переводы строк»; это самый частый случай — почистить ввод пользователя от
случайных пробелов по краям. Вывод:

```text
uppercaseString:       ПРИВЕТ
lowercaseString:       привет
capitalizedString:     Мир Добра
trim:                  'hello world'
```

Кавычки вокруг `'hello world'` я поставил нарочно, чтобы было видно: края
вычищены, а пробел между словами остался на месте.

## Разбиение, склейка и неизменяемая «дописка»

Переходим к `15-mutate.m`. Сначала — операции, которые рождают новые
строки (получатель остаётся прежним).

```objc
NSString *csv = @"яблоко,банан,груша";
NSArray<NSString *> *parts = [csv componentsSeparatedByString:@","];
NSLog(@"частей после split:    %lu", (unsigned long)[parts count]);
NSLog(@"вторая часть:          %@", parts[1]);

NSString *joined = [parts componentsJoinedByString:@" | "];
NSLog(@"joined:                %@", joined);
```

`componentsSeparatedByString:` режет строку по разделителю и возвращает
`NSArray` кусков (массивы — тема главы 17, пока достаточно знать, что
`count` даёт число элементов, а `parts[1]` — второй из них). Запись
`NSArray<NSString *> *` в угловых скобках — подсказка компилятору «внутри
лежат строки»; без неё код работает так же, подробно — в главе 22. Обратная
операция `componentsJoinedByString:` живёт уже на массиве: склеивает его
элементы в одну строку, вставляя между ними разделитель.

```objc
NSString *base = @"Лог";
NSString *one = [base stringByAppendingString:@": старт"];
NSString *two = [one stringByAppendingFormat:@" (код %d)", 200];
NSLog(@"appendString:          %@", one);
NSLog(@"appendFormat:          %@", two);
NSLog(@"base не изменилась:    %@", base);
```

`stringByAppendingString:` приклеивает другую строку в конец и возвращает
**новую** строку. `stringByAppendingFormat:` — то же, но хвост собирается
по образцу формата. Ключевая деталь в последней строке вывода:

```text
частей после split:    3
вторая часть:          банан
joined:                яблоко | банан | груша
appendString:          Лог: старт
appendFormat:          Лог: старт (код 200)
base не изменилась:    Лог
```

`base` так и осталась `«Лог»`. Мы её не меняли — `stringByAppendingString:`
создал отдельную строку, а `base` неизменяема по определению. Это и есть
неизменяемость в действии.

## NSMutableString: строку можно менять

Собирать строку из десяти кусков через десять `stringByAppending...` —
расточительно: каждый шаг плодит новый объект, а промежуточные тут же
выбрасываются. Для случаев, когда строку надо собирать или править
по месту, есть `NSMutableString` — **изменяемый** наследник `NSString`.

> **Отличие от Си.** В Си «изменяемость» строки — это просто наличие
> места в буфере `char buf[64]`, и ты сам стережёшь, чтобы не вылезти за
> край (глава 4, привет `strcpy` и переполнению). `NSMutableString` растёт
> сам: добавляешь текст — он сам выделит память. Никаких буферов и подсчёта
> байтов руками.

```objc
NSMutableString *log = [NSMutableString stringWithString:@"["];
[log appendString:@"GET"];
[log appendFormat:@" /users?page=%d", 2];
[log appendString:@"]"];
NSLog(@"mutable собрали:       %@", log);

NSUInteger n = [log replaceOccurrencesOfString:@"users"
                                    withString:@"clients"
                                       options:0
                                         range:NSMakeRange(0, [log length])];
NSLog(@"замен сделано:         %lu", (unsigned long)n);
NSLog(@"после замены:          %@", log);

[log insertString:@"HTTP " atIndex:1];
NSLog(@"после вставки:         %@", log);
```

Разбираем методы, которых нет у неизменяемого `NSString` — они меняют
**сам объект** и обычно ничего не возвращают (`void`):

- `appendString:` — дописывает строку в конец прямо в этот объект.
- `appendFormat:` — то же, но хвост по образцу формата.
- `replaceOccurrencesOfString:withString:options:range:` — заменяет все
  вхождения одной подстроки на другую **в указанном диапазоне**.
  `options:0` — без особых правил поиска; `range` обычно вся строка,
  поэтому пишем `NSMakeRange(0, [log length])`. Этот метод как раз
  **возвращает** число сделанных замен — единственный с возвратом.
- `insertString:atIndex:` — вставляет строку начиная с указанной позиции,
  раздвигая остальное.

Вывод:

```text
mutable собрали:       [GET /users?page=2]
замен сделано:         1
после замены:          [GET /clients?page=2]
после вставки:         [HTTP GET /clients?page=2]
```

Заметь: `stringWithString:` создаёт изменяемую копию из обычной строки —
удобный старт. И ещё: раз `NSMutableString` — наследник `NSString`, его
можно передавать всюду, где ждут `NSString`. Обратное неверно: где ждут
`NSMutableString`, обычную `NSString` не подсунешь, у неё нет `appendString:`.

> **Частая ошибка.** Свойство объявлено `@property (copy) NSString *name;`
> (глава 8), ты присвоил ему `NSMutableString`, продолжаешь менять его
> снаружи и ждёшь, что правки появятся в свойстве. Не появятся: `copy`
> сделал неизменяемый снимок в момент присвоения. И это не баг, а ровно
> та причина, по которой строковые свойства помечают `copy`, а не
> `strong`: никто снаружи не перепишет текст объекта у него за спиной.

## Число ↔ строка

Текст из поля ввода приходит строкой, а считать надо числом. И наоборот —
число надо показать строкой. Оба перехода есть в конце `15-create.m`:

```objc
NSString *priceText = @"199.90";
NSString *countText = @"7 штук";
NSLog(@"doubleValue:    %.2f", [priceText doubleValue]);
NSLog(@"intValue:       %d", [countText intValue]);

double total = [priceText doubleValue] * [countText intValue];
NSString *totalText = [NSString stringWithFormat:@"%.2f тенге", total];
NSLog(@"итог строкой:   %@", totalText);
```

`[priceText doubleValue]` читает из строки дробное, `[countText intValue]`
— целое, а обратно число превращаем в текст знакомым `stringWithFormat:`
через `%d`/`%f`. `intValue`/`doubleValue` терпимы к мусору: `«7 штук»`
даст `7`, разбор пропускает пробелы в начале и останавливается на первом
нечисловом символе. Вывод:

```text
doubleValue:    199.90
intValue:       7
итог строкой:   1399.30 тенге
```

> **Подводный камень `intValue`.** Если строка вообще не начинается с
> цифры (`«abc»`), вернётся `0` — и ты не отличишь «там был ноль» от «там
> была не цифра». Когда важно знать, удался ли разбор, бери `NSScanner`
> или `NSNumberFormatter` (оба описаны в документации Foundation, в книге
> мы их не разбираем); `intValue` хорош для быстрых прикидок, где
> `0`-по-умолчанию устраивает.

## NSAttributedString — строка с оформлением

Кратко, для общей картины. `NSString` хранит только сам текст, без вида:
шрифта, цвета, жирности. Когда тексту нужно оформление — например, часть
слова красная и жирная, — берут `NSAttributedString`: это текст плюс
набор **атрибутов** (attributes), привязанных к диапазонам символов.

Им рисуют форматированные подписи, ссылки внутри текста, цветные куски в
интерфейсе. У него тоже есть изменяемый собрат — `NSMutableAttributedString`.
Глубоко мы его здесь не трогаем: он живёт ближе к UIKit/AppKit, где есть
что раскрашивать. Просто знай: если спросят «как сделать слово в подписи
красным», ответ — `NSAttributedString`, а не `NSString`.

## Строим с нуля: нормализатор логина

Соберём из изученного маленькую честную задачу. Пользователь вводит логин
как попало: с пробелами по краям, в разном регистре, иногда с ведущей `@`
(привычка из соцсетей). Нам нужно привести всё к единому виду: без
пробелов, в нижнем регистре, без `@` в начале. Пустой ввод — отвергнуть.

### Шаг 1. Наивная версия

Первая мысль — просто перевести в нижний регистр:

```objc
NSString *normalizeUsername(NSString *raw) {
    return [raw lowercaseString];
}
```

Прогоним мысленно на `«  @Ivan_KZ  »`. Получим `«  @ivan_kz  »`. Регистр
поправили, но пробелы по краям остались, и `@` тоже. Логин `«  @ivan_kz  »`
и `«ivan_kz»` система сочтёт разными людьми. Плохо.

### Шаг 2. Срезаем пробелы

Добавим обрезку краёв перед сменой регистра:

```objc
NSCharacterSet *ws = [NSCharacterSet whitespaceAndNewlineCharacterSet];
NSString *s = [raw stringByTrimmingCharactersInSet:ws];
s = [s lowercaseString];
```

Теперь `«  @Ivan_KZ  »` → `«@ivan_kz»`. Пробелы ушли, регистр в норме.
Осталась ведущая `@`.

### Шаг 3. Снимаем ведущую `@`

Проверим префикс и, если он есть, отрежем первый символ:

```objc
if ([s hasPrefix:@"@"]) {
    s = [s substringFromIndex:1];
}
```

`hasPrefix:@"@"` отвечает, начинается ли строка с собачки.
`substringFromIndex:1` берёт всё начиная со второго символа — то есть
выбрасывает `@`. `«@ivan_kz»` → `«ivan_kz»`.

### Шаг 4. Отвергаем пустой ввод

Если пользователь ввёл одни пробелы, после обрезки строка станет пустой.
Вернём `nil` — пусть вызывающий код решит, что делать:

```objc
if ([s length] == 0) {
    return nil;
}
```

### Полная функция

Складываем шаги в одну функцию:

```objc
NSString *normalizeUsername(NSString *raw) {
    NSCharacterSet *ws = [NSCharacterSet whitespaceAndNewlineCharacterSet];
    NSString *s = [raw stringByTrimmingCharactersInSet:ws];
    s = [s lowercaseString];
    if ([s hasPrefix:@"@"]) {
        s = [s substringFromIndex:1];
    }
    if ([s length] == 0) {
        return nil;
    }
    return s;
}
```

В `main` (целиком — в `15-normalize.m`) прогоняем её по списку грязных
вводов через `for (NSString *input in inputs)` — это **быстрый перебор**
(fast enumeration): пройтись по элементам массива по очереди, без индексов
(подробно — в главе 17). Запускаем:

```text
clang -fobjc-arc -framework Foundation -Wall -Wextra -O2 \
      code/15-normalize.m -o /tmp/t && /tmp/t
```

```text
'  @Ivan_KZ  ' -> 'ivan_kz'
'SERIK' -> 'serik'
'@Astana2026' -> 'astana2026'
'     ' -> ОТКЛОНЁН (пусто)
```

Четыре разных «грязных» ввода — четыре правильных исхода. Заметь, что вся
функция собрана из методов, которые мы разобрали по дороге, и ни в одном
месте мы не лазали в байты руками. Это и есть выигрыш `NSString` над
`char *`: задача читается как описание словами.

## Частые ошибки

- **`==` вместо `isEqualToString:`.** `==` сравнивает адреса объектов, а
  не текст. Иногда «срабатывает» случайно (на одинаковых литералах
  компилятор может вернуть один и тот же объект) — и тем коварнее: код
  работает на тестах и падает на данных из сети. Для текста всегда
  `isEqualToString:`.
- **`length` как «число символов».** Для эмодзи и составных символов
  `length` больше, чем видит человек. Не нарезай по таким индексам строку
  с юникодом — порежешь символ пополам.
- **Забыл проверку `NSNotFound`.** `rangeOfString:` при неудаче кладёт в
  `location` гигантское `NSNotFound`, а не `0`. Используешь его как индекс
  без проверки — падение.
- **Меняешь immutable-строку.** `NSString` менять нельзя; `appendString:`
  у него просто нет. Нужно менять по месту — бери `NSMutableString`.
- **Сохранил `UTF8String` надолго.** Указатель временный, привязан к пулу
  автоосвобождения. Используй сразу или копируй байты.
- **`NSUInteger` без приведения.** `length`/`count` — это `NSUInteger`.
  Печатай как `(unsigned long)[s length]` с `%lu`. С `%d` компилятор
  предупредит, а голый `%lu` без приведения на 64-битном Mac пройдёт
  молча, но на платформе, где `NSUInteger` — `unsigned int`, формат
  разъедется.

## Упражнения

1. Напиши функцию, которая принимает email и возвращает его доменную часть
   (после `@`). Используй `rangeOfString:` и `substringFromIndex:`. Не
   забудь про `NSNotFound`, если `@` нет.
2. Дополни `normalizeUsername`: отвергай логин, если в нём остались
   пробелы внутри (подсказка — `rangeOfString:@" "`).
3. Собери из массива слов `@[@"Objective", @"C", @"с", @"нуля"]` одну
   строку через пробел двумя способами: `componentsJoinedByString:` и
   циклом с `NSMutableString`. Сравни код.
4. Возьми строку с эмодзи и посчитай в ней «человеческие» символы через
   `enumerateSubstringsInRange:options:usingBlock:` с
   `NSStringEnumerationByComposedCharacterSequences`. Сверь с `length`.
5. Напиши функцию-«цензор»: замени в тексте все вхождения слова на
   звёздочки той же длины через `NSMutableString` и
   `replaceOccurrencesOfString:withString:options:range:`.
6. Проверь на себе ловушку `==`: создай две строки с одинаковым текстом
   через `stringWithFormat:` и сравни их и `==`, и `isEqualToString:`.
